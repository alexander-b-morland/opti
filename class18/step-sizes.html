Step sizes and starting points

The theorems assume \(\alpha = 1/M\), but in practice nobody hands you \(M\). This part is about the two choices you do control, the step size and the starting point, and how they decide both the speed and the destination of gradient descent.

The step-size trade-off

The core trade-off in setting the step size has two failure modes:

  • Too small: each iteration makes little progress, and convergence is slow.
  • Too large: the first-order approximation stops being accurate, the iterate overshoots, and the behaviour becomes unstable.

In between, convergence can be much faster. Part c gave one safe choice, \(\alpha = 1/M\). When \(M\) is unknown, the step size is something you tune.

Small, medium and large steps

Interactive

Gradient descent on a convex bowl

Switch between a small, a medium and a large step, or set \(\alpha\) with the slider. Click on the plot to start from a new point. The cross marks the minimum. Iterations stop when \(\|\nabla f\| < 10^{-4}\).

This mirrors the lecture's two-dimensional illustration:

  • Small step: the path is smooth and heads the right way, but it takes hundreds of iterations.
  • Medium step: the same destination in a few dozen iterations.
  • Large step: the iterates overshoot and bounce from side to side. They still arrive here, but more slowly than with the medium step. Push \(\alpha\) a little further, to about 0.5, and they diverge.

The function is convex, so every run that converges ends at the same minimum. The step size only changes how long it takes.

The starting point

Gradient descent is guaranteed to find a stationary point, but not a global minimum when \(f\) is not convex. The starting point can decide which stationary point the algorithm converges to.

Interactive

Two valleys

Click on the left half and on the right half of the plot. Watch which minimum each start reaches. Then keep the default start and switch to the large step.

A simple remedy from the lecture: run the algorithm in parallel from several starting points, and keep the best output across all of them.

Step size and start together

The lecture's last point: the starting point and the step size can be tuned together, both to avoid local minima and to speed up convergence. The widget above shows it. From the default start on the right, the small and the medium step settle in the worse right-hand valley. The large step overshoots the ridge in the middle and ends in the global minimum on the left. That is luck, not a guarantee. A slightly different step or start can give the opposite result.

Summary

  • Step size: too small is slow, too large is unstable. In between, convergence is fastest.
  • Convex \(f\): every start reaches the global minimum. The step size decides how fast.
  • Non-convex \(f\): the start can decide which local minimum you reach. Use several starts and keep the best.
  • Step size and starting point can be tuned together, to avoid local minima and to converge faster.
How this shows up on the exam

"The larger the step size, the faster the convergence" is a favourite statement to judge. The right answer is that we do not know in general: larger steps help only while the function keeps decreasing along the direction.

You may also be shown contour plots with iterate paths and asked to match each to a method. Steady steps against the gradient are gradient descent. Wobbly, noisy paths are stochastic gradient descent (class 19). Very few, direct steps are Newton's method (class 20).

Check yourself
Quick check
Gradient descent with a constant step size runs on a convex, differentiable function. You double the step size. Which is true?
A larger step makes more progress per iteration only while the first-order approximation stays accurate. In the widget, going from the small to the medium step speeds things up, going from the medium to the large step slows them down, and a bit further the iterates diverge.
Quick check
\(f\) is not convex. You run gradient descent from five starting points and get five different stationary points. What does the lecture suggest?
Running from several starting points and keeping the best output is the lecture's remedy for local minima. An average of local minima need not be a good point at all, and a smaller step does not change which valley a start falls into.
