The knapsack recursion

Dynamic programming solves a big problem by solving many small ones in the right order and storing their answers. The knapsack problem shows the whole idea in one table.

The binary knapsack problem

There are \(n\) items. Item \(j\) has value \(c_j\) and weight \(w_j\). The knapsack carries at most \(K\). Choose \(x_j \in \{0, 1\}\) (take item \(j\) or not):

\[ \max\ \sum_{j=1}^n c_j x_j \quad \text{s.t.}\quad \sum_{j=1}^n w_j x_j \le K,\quad x_j \in \{0, 1\}. \]

Branch-and-cut (class 11) is one way to solve it. Dynamic programming is another, completely different one.

Smaller problems of the same kind

Define \(C_i(\kappa)\) as the best value achievable with only the first \(i\) items and capacity \(\kappa\):

\[ C_i(\kappa) = \max\ \Big\{ \sum_{j=1}^i c_j x_j \ :\ \sum_{j=1}^i w_j x_j \le \kappa,\ x_j \in \{0, 1\} \Big\}. \]

The original problem is \(C_n(K)\). Problems with few items and small capacity are easy. The question is how to build \(C_n(K)\) from them, in sequence.

The recursion

Suppose you are in the "state" \((i + 1, \kappa)\): you are deciding about item \(i + 1\) with capacity \(\kappa\) left. There are only two choices.

Do not select item \(i+1\)

Gain nothing. Move to state \((i, \kappa)\).

Select item \(i+1\)

Gain \(c_{i+1}\). Use \(w_{i+1}\) of the capacity. Move to state \((i, \kappa - w_{i+1})\).

Recursive relationship
\[ C_{i+1}(\kappa) = \max\Big\{ \underbrace{C_i(\kappa)}_{\text{skip } i+1},\ \ \underbrace{c_{i+1} + C_i(\kappa - w_{i+1})}_{\text{take } i+1} \Big\} \]

Initial conditions: \(C_1(\kappa) = 0\) if \(0 \le \kappa < w_1\), and \(c_1\) if \(\kappa \ge w_1\). And \(C_i(\kappa) = -\infty\) for \(\kappa < 0\), which forbids overfilling.

The principle behind it

Whatever you decide about item \(i + 1\), the rest of the decision must be optimal for the problem that remains. An optimal solution is built from optimal solutions of subproblems. That is the principle of optimality, and it is what every dynamic program rests on.

Filling the table

Interactive

Dynamic programming, one cell at a time

Four items, capacity 7. The gold cell is being computed. The teal cells above are the two subproblems it uses: skip (directly above) and take (above, \(w_i\) columns to the left).

The table is filled row by row, so each cell only needs values that already exist. At the end, reading the table backwards (where did the value change?) recovers which items to take.

Why it is fast

When weights and capacity are integers, there are \(n \times (K + 1)\) states \((i, \kappa)\), and each takes constant time. So the algorithm runs in \(O(nK)\), compared with \(2^n\) subsets for brute-force enumeration.

A subtlety

\(O(nK)\) is polynomial in the value of \(K\), not in the number of digits needed to write it. With a capacity of a billion, the table has a billion columns. This is called pseudo-polynomial. It is a first glimpse of the curse of dimensionality in part b.

Summary

  • Define small subproblems of the same form: \(C_i(\kappa)\).
  • Relate them by a recursion over the decision for one item: skip or take.
  • Solve them in order and store the answers. \(O(nK)\) instead of \(O(2^n)\).
Check yourself
Quick check
\(C_2(5) = 16\) and \(C_2(1) = 0\). Item 3 has value 12 and weight 4. What is \(C_3(5)\)?
\(\max\{C_2(5),\ 12 + C_2(1)\} = \max\{16, 12\} = 16\). Skipping item 3 is better here.
