Class 16 · Optimization under uncertainty

Dynamic programming

When decisions unfold over time and chance intervenes between them, solve backward: first the last decision, then the one before it, storing what each situation is worth.

Overview

The big picture

Class 15 had two stages. Many problems have dozens: decide, observe, decide again. Dynamic programming handles any number of stages, any non-linearity and any uncertainty, as long as the state stays small.

Planning a road trip backward. If you know how long it takes to reach the destination from every town on the last day, you can figure out the best town to stop in on the second-to-last day. From there, the day before. By the time you reach today, you know the best first move, and a rule for every situation you could end up in.

\[ J_k(x_k) = \min_{u_k \in U_k(x_k)} \mathbb{E}\big[ g_k(x_k, u_k) + J_{k+1}(f_k(x_k, u_k)) \big], \qquad J_N = g_N. \]

The value of being in state \(x_k\) is the best decision's immediate cost plus the expected value of where it takes you.

Dynamic programming is the foundation of reinforcement learning. It gives exact answers for small problems, simple and interpretable policies (order-up-to levels, hiring thresholds), and a language for thinking about any sequential decision.

Takeaways from the lecture
  1. Dynamic programming handles sequential decisions with non-linearities and uncertainty.
  2. The model: states, actions, transition functions, per-period costs and terminal costs.
  3. Bellman's equation is a recursion that is solved by backward induction.
  4. The curse of dimensionality motivates approximate dynamic programming and reinforcement learning.

Knapsack\(C_{i+1}(\kappa) = \max\{C_i(\kappa),\ c_{i+1} + C_i(\kappa - w_{i+1})\}\)
\(C_i(\kappa) = -\infty\) for \(\kappa < 0\). \(O(nK)\).
Bellman\(J_N = g_N\)
\(J_k(x) = \min_u \mathbb{E}[g_k(x, u) + J_{k+1}(f_k(x, u))]\)
Policy \(\mu_k(x)\) = the argmin.
Inventory\(x_{k+1} = \max(x_k + u_k - d_k, 0)\)
Order-up-to: \(u = S_k - x\) if \(x < s_k\), else 0.
Recruiting\(J_k(x) = \max\{x,\ \mathbb{E}[J_{k+1}(s_{k+1})]\}\)
Hire iff score \(\ge\) value of continuing. Bar falls over time.

Exam practice

Test yourself

Multiple choice in the style of the midterm. Say your one-line justification before you click.

Question 1 · Recursion
Items: \((c, w) = (6, 2), (10, 3)\). Capacity \(K = 4\). What is \(C_2(4)\)?
\(C_1(4) = 6\) and \(C_1(1) = 0\). So \(C_2(4) = \max\{6,\ 10 + C_1(1)\} = 10\). Both items together weigh 5, more than 4.
Question 2 · Complexity
The knapsack DP runs in \(O(nK)\). Why is it not considered a polynomial-time algorithm for the knapsack problem?
It is pseudo-polynomial: polynomial in the numeric value of \(K\), not in the input size.
Question 3 · Modeling
In the inventory model, why is the inventory level a valid state?
A state must summarize everything from the past that affects the future. Past orders and demands matter only through the current stock.
Question 4 · Bellman
In the recruiting problem with \(n\) candidates, what is the hiring threshold for the last candidate?
\(J_{n+1} = 0\), so the value of continuing after the last candidate is 0. Any score beats it.
Question 5 · Policy shape
If the fixed ordering cost \(F\) is set to 0, what happens to the order-up-to policy?
With no fixed cost there is no reason to delay a small order, so the reorder point coincides with the target (a base-stock policy).
Question 6 · Dimensionality
A DP has 20 periods, a state with 3 components of 50 values each, and 10 decisions. Roughly how many state-decision pairs per period must be evaluated?
\(50^3 = 125{,}000\) states times 10 decisions. Add a few more state components and it becomes impossible: the curse of dimensionality.
